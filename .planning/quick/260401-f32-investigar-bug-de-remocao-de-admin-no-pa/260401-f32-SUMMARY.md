# Quick Task 260401-f32: Fix requireAdmin() JWT Caching Bug

**One-liner:** requireAdmin() now reads role from the Supabase auth DB via getUserById(), immediately rejecting downgraded users instead of waiting up to 1 hour for JWT expiry.

## What Was Fixed

The original `requireAdmin()` checked `user?.app_metadata?.role` from the session JWT returned by `getUser()`. While `getUser()` validates the session cookie on every call, the JWT payload is only refreshed when the JWT expires (default: 1 hour). This meant:

1. Admin grants user "member" role via the admin panel
2. `updatePermissions()` calls `admin.auth.admin.updateUserById()` — DB is updated immediately
3. The downgraded user's active JWT still carries `app_metadata.role = "admin"` until it expires
4. For up to 1 hour, the downgraded user can continue calling all five admin Server Actions

## The Fix

Two-step check in `requireAdmin()`:

1. `supabase.auth.getUser()` — validates the session cookie (returns `null` if revoked or expired). Gives us `user.id`.
2. `admin.auth.admin.getUserById(user.id)` — queries the Supabase auth DB directly for the authoritative role. Bypasses the JWT payload entirely.

If either check fails or the DB role is not `'admin'`, throws `'Unauthorized'`.

All five exported Server Actions (`createMember`, `updatePermissions`, `disableMember`, `reactivateMember`, `deleteMember`) call `requireAdmin()` as their first operation — they are all protected by the fix without any changes to their bodies.
